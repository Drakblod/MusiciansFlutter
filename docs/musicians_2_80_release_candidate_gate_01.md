## Rules and privacy boundaries

Additional local release fix: `/PublicEvents/$eventId/.write` now requires exact `createdBy` ownership on creation and existing ownership on update/delete; updates cannot transfer or remove ownership. Missing legacy ownership fails closed. The public calendar and details UI use the same exact-creator condition. No public-read policy changed.

Projection roots remain server-owned. No legacy client write fallback is restored.

Metadata publication is server-only. An opaque upload ID is not publication authority; Map object binding and canonical pin write are atomic. Pin removal/replacement makes the former object's public-read predicate false. Public-image tokens are expected because those objects are public by contract.
